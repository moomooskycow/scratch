scripts – Build and release automation for fd

The scripts directory holds three shell and AWK scripts that automate the creation of Debian packages, help-text updates, and version bumps for the fd project. These scripts keep the release process reproducible and reduce manual error.

3Scripts
Bash + AWKLanguages

What each script does

The script create-deb.sh builds a Debian package from the compiled fd binary. It sets metadata like maintainer and version, installs the binary, man page, autocompletion files, README, licenses, and a copyright file, then runs dpkg-deb to produce a .deb artifact.

update-help.awk is an AWK script that replaces the code block under "Command-line options" in the documentation with fresh output from 'fd -h', ensuring the help text stays in sync with the current CLI.

version-bump.sh automates the "Version bump" section of a release: it creates a release branch, updates the version in Cargo.toml, synchronizes the MSRV mention in README.md, and writes the version header into CHANGELOG.md.

Seams and sharp edges

Each script has a single, well-defined job

create-deb.sh builds a package, update-help.awk refreshes inline help, and version-bump.sh prepares a release. This separation makes each script easy to test and maintain independently.

What can hurt a maintainer

If the fd binary or its help output changes format, update-help.awk may silently produce incorrect output or fail to match the expected code-block markers, breaking documentation builds.

How these scripts fit into the release workflow

Release pipeline overview

During a typical release, a maintainer runs version-bump.sh first to update version strings and create a release branch. Then the CI pipeline invokes create-deb.sh to produce the Debian package for the target architecture. The update-help.awk script is run manually or as part of a doc generation step to keep the help text accurate.
