The Behavioral Safety Net for fd

This directory holds the black-box tests that run the real fd program against real temporary directories and check its output line by line. Every flag, filter, and edge case fd supports gets a test here that spins up files, invokes the compiled binary, and compares what came back against what should have come back.

How the tests hold together

Everything in this directory lives in one file, tests/tests.rs, which pulls in a shared sandbox helper module and a fixed cast of directories and files reused across most tests.

Two static lists, DEFAULT_DIRS and DEFAULT_FILES, define the standard fixture: a nested tree with mixed-case names, ignored files, and a file with a space in it. Almost every test builds a fresh environment from these lists, runs fd with some combination of flags, and asserts the exact expected output.

Each test is self-contained: it creates its own temporary directory through the shared testenv helper, so tests can run in parallel without stepping on each other's files, symlinks, or ignore rules.

Seams and sharp edges

Output must match exactly, line for line

Assertions compare fd's stdout against a hand-written expected string. Case sensitivity, sort order, and path separators are all part of the contract being pinned, not incidental details.

Platform gates are easy to break silently

Many tests are wrapped in #[cfg(unix)] or #[cfg(not(windows))]guards because symlinks, executable bits, and file-system boundaries behave differently across operating systems. Forgetting a platform gate breaks CI on the other OS, not locally.

Path separators are a footgun the tests actively guard against

A pattern containing a forward slash without --full-pathused to silently return zero results when someone pasted a full path by mistake; tests now pin the diagnostic that fires instead.

--and patterns follow the same rules as the primary pattern

Whatever validation and matching behavior applies to the main search pattern, including the path-separator diagnostic and glob or fixed-string handling, must also apply identically to each --and pattern.

What the test suite actually covers

Coverage areas

Matching modes get their own clusters: regex versus glob versus fixed-strings, smart case versus explicit case sensitivity, and exact non-substring matching.

Filesystem semantics are exercised heavily: hidden files, .gitignore and .fdignore precedence, global ignore files, symlink following, broken symlinks, and one-file-system boundaries.

Depth and pruning tests check --max-depth, --min-depth, --exact-depth, and --prune against the same nested fixture, confirming boundary counting is consistent.

Execution tests cover --exec and --exec-batch, including placeholder substitution, multiple exec commands chained with a semicolon separator, batch size limits, and error messages for invalid combinations like two placeholders in one batch command.

Metadata filters round things out: file size ranges with byte and kibibyte units, modification time windows using both relative and absolute timestamps, and Unix file ownership by uid, gid, and name.
