How fd formats file paths for output

This module controls the final textual representation of every search result. When fd finds a file, it passes the path through a format template that can include the full path, the basename, the parent directory, or a version with the extension removed. The code handles all the edge cases around path components, escaped braces in templates, and platform-specific separator behaviour.

Parsing a format string into tokens

Users supply an output format via the --format flag, often including placeholders like {} for the full path or {/} for the basename. The parse method scans the string with an Aho-Corasick automaton, splitting it into a sequence of Token variants. Escaped braces are handled so that literal {{ and }} become single characters in the output.

If no placeholder is found, the format string is stored as FormatTemplate::Text and returned verbatim. Otherwise the result is a vector of tokens that can be evaluated per path.

Generating the final formatted string

The generate method walks the token list and produces an OsString. For each placeholder it calls the corresponding helper from input.rs: basename extracts the file name, dirname extracts the parent, and remove_extension strips the suffix. An optional custom path separator can be supplied; the replace_separator function handles Windows prefix components like UNC paths by rendering them without converting backslashes.

Seams and sharp edges

Placeholder tokens always produce a non-empty string

Each placeholder variant maps to a path-computing function that returns an OsString even for edge cases like an empty path or a root directory.

Escaped braces must be carefully paired

The parser treats {{ and }} as single brace characters, but a placeholder followed by an unescaped closing brace can cause an unexpected token. Maintainers adding new placeholders must update both the Aho-Corasick pattern list and the token_from_pattern_id match arm.
