Executing Commands from Search Results

The exec module turns file search results into commands. It takes the paths found by the walker, builds command strings using placeholders like {} or {.}, and then runs them one by one or in batches. It handles output buffering, exit codes, and errors such as a missing executable.

How Command Execution Works

The module is split across three files. The public interface in mod.rs defines CommandSet and ExecutionMode. A CommandSet holds one or more CommandTemplate values, each parsed from user-provided arguments. When you run fd --exec, each matched path triggers execute() which generates a Command and runs it. For --exec-batch, paths are accumulated until a size or argument-length limit is reached, then execute_batch() fires them together.

Low-level execution lives in command.rs, which provides execute_commands() and handle_cmd_error(). The OutputBuffer struct collects stdout and stderr from each command, then flushes them all at once. Output buffering is controlled by a flag: when running on a single thread, output passes through immediately so the user sees live results.

The job dispatcher in job.rs connects the walker results to the command system. The job() function processes each WorkerResult individually, while batch() collects paths and hands them to execute_batch(). Both functions merge exit codes across all commands, returning a single error status if any command failed.

Seams and sharp edges

Placeholder behavior is consistent

Every command template must contain at least one placeholder like {} or {.}. If the user omits one, a placeholder is automatically appended to the end of the command. For batch commands, only one placeholder is allowed and it must not be the executable itself.

Missing executables

If the command binary cannot be found, handle_cmd_error prints a clear error message and returns GeneralError. Other I/O errors—such as permission denied—are also caught and reported.

Exit code propagation

When any command fails with a non-zero exit code, the loop stops early and the error is returned immediately. In batch mode, the worst exit code is preserved using merge_exitcodes.

Internal details and edge cases

CommandBuilder internals

The CommandBuilder struct manages the lifecycle of a batch command. It splits the template into pre-args, path arg, and post-args. When push() is called, it checks the ARG_MAX limit and finishes the current batch before adding more paths. This ensures the spawned command never exceeds the system's maximum argument size.

Seams and sharp edges

Empty command list

If the user supplies no arguments at all, CommandTemplate::new returns an error. This prevents accidentally running every file as an executable.
