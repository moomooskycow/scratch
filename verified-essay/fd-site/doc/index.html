Documentation and assets for fd

The doc directory holds the official man page, logos, a release checklist, a screencast generator, and sponsorship information for the fd project — a fast, user-friendly alternative to the classic find command.

What lives here and why it matters

The doc directory provides the single authoritative man page fd.1 that documents every option, flag, and execution mode the man page defines the entire CLI surface. Logos appear in both raster (PNG) and vector (SVG) forms, generated by Inkscape the logo SVG was created with Inkscape. A shell script drives an SVG screencast that demonstrates common fd invocations the screencast script simulates a terminal session. The release checklist guides maintainers through version bumps, pre-release checks, and publication the checklist covers the full release workflow. Sponsorship is acknowledged in a dedicated Markdown file sponsors are thanked with a neutrality statement.

An invariant: the man page must remain in sync with the CLI help output. Outdated documentation is a common source of user frustration. No sharp edges exist in this directory beyond the need to keep prose current.

Seams and sharp edges

Man page drift

Every release adds or deprecates flags; doc/fd.1the option list must be regenerated when flags change must be regenerated to match.

Orchestrated release process

A release involves version bumps, CHANGELOG updates, CI verification, and crate publication; missing any step stalls the release the checklist details every required step.
